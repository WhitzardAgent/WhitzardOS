---
title: QitOS Studio
description: Run registered Agents in a local conversation workbench and inspect durable facts.
---

QitOS Studio is an optional local Web client for any registered QitOS Agent. It uses the canonical `AgentModule`, `Engine`, durable Session and Trajectory contracts. An Agent can start with only an `agent.yaml`; an application can add a Python factory and optional Studio adapter without writing frontend code. The adapter describes presentation and a follow-up task strategy. It cannot grant filesystem, network, tool or model permissions.

## Install and start

The QitOS wheel includes built Web assets. Node.js is needed only to rebuild `studio-web` from source. Put this operator-owned registry beside your Agent configuration:

```yaml
agents:
  - id: default
    name: Default Agent
    description: A declarative Agent.
    config: agent.yaml
  - id: custom
    name: Custom Agent
    config: agent.yaml
    factory: my_agent:make_agent
    studio_adapter: my_agent:StudioAdapter
```

`config` resolves relative to the registry. The factory receives the existing composition's `config`, `model`, `tool_registry`, `protocol` and `parser`. `studio_adapter` is an optional `module:callable` whose instance implements `capabilities()` and `continuation_task(turns, message)`. Both references are specified only in the local registry; browser requests cannot import modules or submit paths. See [the standalone coding reference](https://github.com/WhitzardAgent/WhitzardOS/tree/master/examples/projects/studio_coding) and [the declarative/non-coding sample](https://github.com/WhitzardAgent/WhitzardOS/tree/master/examples/studio).

```bash
qit studio --registry studio.yaml --credentials ~/.config/qitos/credentials.yaml
```

Studio binds `127.0.0.1:8766`, opens the browser, and stores its local launch index in `.qitos/studio.sqlite3` next to the registry unless `--state` is set. Each Agent must use a durable SQLite Session and enabled Trajectory. Use an explicit model configuration and credential reference; do not put keys in the registry. `qita board/replay/export` remain available.

A reproducible [local Docker image](https://github.com/WhitzardAgent/WhitzardOS/tree/master/docker/studio) packages the same Studio service. Use host networking on Linux because the listener is intentionally loopback-only; bind mounting an Agent project does not install its Python package or provision its Docker Env.

## Conversation and observation

The left rail searches loaded conversations and pages through history; conversations can be renamed, pinned and archived. The center keeps user requests, Agent results and saved process facts in order, with a persistent composer. The right inspector separates timeline, tools, WorkGraph, artifacts and diagnostics. File and diff tabs appear only when an application declares them; a tab with no saved facts says so explicitly. The UI defaults to Chinese and can switch fully to English, with light/dark themes and a narrow-screen drawer.

A Studio conversation contains one or more **turns**. Each turn creates a distinct runtime Session. An optional adapter may compose a follow-up task after the last turn ends; the original terminal Session remains terminal. The response retains the input message separately from the composed task. A manual resume of an eligible paused Session creates a new run identity under that Session, and old run identities remain queryable. Studio never treats an open SSE connection as evidence that a task succeeded.

The browser closing does not stop a run. After a service restart, history and persisted facts remain readable; an unobserved in-flight process is shown as `unknown`. A saved `paused` or `waiting_input` Session may be manually restored only when its configuration digest and runtime capability match. A changed factory or config may make restoration unavailable.

**Current control limit:** the runtime does not yet provide a durable, cross-process approval resolver or general stop/cancel receipt. Studio therefore does not present working approval, pause, cancel, or steer controls. The reference coding Agent inherits this limit. Do not use a Studio continuation as a substitute for approval of a pending tool call.

## Local API

- `GET /api/agents` and `GET /api/agents/{id}/capabilities` list local registry entries and declared presentation capabilities.
- `GET /api/sessions?page=1&limit=50&before={id}` pages root conversations. `POST /api/sessions/search` submits bounded search text in a CSRF-protected JSON body, never in a URL. `GET /api/sessions/{id}/turns?after=N` pages their turns; `GET /api/sessions/{turn_id}/runs` lists recorded run identities. Legacy V1 launches migrate to one-turn conversations without invented missing runs.
- `POST /api/sessions` accepts only `agent_id` and `task`. `POST /api/sessions/{conversation_id}/messages` accepts `message` only when the adapter and current state allow continuation. `PATCH /api/sessions/{conversation_id}` updates title, pin or archive metadata. `POST /api/sessions/{turn_id}/resume` invokes the existing Session restore contract.
- `GET /api/sessions/{turn_id}/events?run_id={id}&after=N&limit=100` reads redacted durable Trajectory facts. `GET /api/sessions/{turn_id}/stream` follows them by SSE; clients backfill saved facts on reconnection. A run ID must belong to the requested turn.

Writes require the process cookie, CSRF header, exact loopback Host and Origin. The service does not expose arbitrary host paths, private artifact bodies, or arbitrary imports. API failures return a safe `error_code` rather than raw exceptions.
