title: QitOS Studio
description: 在本地会话工作台运行已登记的 Agent，并检查持久化事实。
---

QitOS Studio 是供开发者使用的可选本地 Web 界面，复用 `AgentModule`、`Engine`、持久化 Session 和 Trajectory。普通 Agent 只需登记 `agent.yaml`；应用可以增加 Python factory 和可选 Studio 适配器，无需编写专用前端。适配器描述展示能力和后续任务的构造策略，不能授予文件、网络、工具或模型权限。

## 安装与启动

QitOS wheel 已包含构建好的页面资源；只有从源码重建 `studio-web` 时需要 Node.js。在 Agent 配置旁创建由操作者维护的清单：

```yaml
agents:
  - id: default
    name: Default Agent
    description: 声明式 Agent。
    config: agent.yaml
  - id: custom
    name: Custom Agent
    config: agent.yaml
    factory: my_agent:make_agent
    studio_adapter: my_agent:StudioAdapter
```

`config` 相对清单解析。factory 接收现有组合的 `config`、`model`、`tool_registry`、`protocol` 和 `parser`。可选 `studio_adapter` 是 `module:callable`，实例实现 `capabilities()` 与 `continuation_task(turns, message)`。这些引用只能写在本地清单；浏览器请求不能提交导入路径或宿主路径。参见[独立 coding 示例](https://github.com/WhitzardAgent/WhitzardOS/tree/master/examples/projects/studio_coding)与[声明式／非 coding 示例](https://github.com/WhitzardAgent/WhitzardOS/tree/master/examples/studio)。

```bash
qit studio --registry studio.yaml --credentials ~/.config/qitos/credentials.yaml
```

Studio 监听 `127.0.0.1:8766`，默认打开浏览器。启动索引默认位于清单旁的 `.qitos/studio.sqlite3`，可通过 `--state` 指定。每个 Agent 必须启用 SQLite 持久化 Session 和 Trajectory。模型配置及凭据引用需显式指定；不要在清单中保存密钥。`qita board/replay/export` 保持可用。

可复现的[本地 Docker 镜像](https://github.com/WhitzardAgent/WhitzardOS/tree/master/docker/studio)打包了同一个服务。在 Linux 上使用 host 网络，以保留仅监听 loopback 的边界；挂载 Agent 项目不等于安装其 Python 包，也不会自动配置应用的 Docker Env。

## 会话与观测

左侧支持搜索已加载会话、分页、重命名、置顶和归档。中央按序展示用户输入、Agent 结果及已保存过程，底部有常驻输入框。右侧检查面板区分时间线、工具、WorkGraph、产出和诊断。应用声明文件或差异能力时才出现对应页签；没有事实时明确显示缺失状态。界面默认中文，可完整切换英文，提供深浅主题与窄屏抽屉。

一个 Studio 会话包含一轮或多轮。**每轮创建独立的运行时 Session**。可选适配器只在上一轮结束后构造后续任务；原来的终态 Session 不会重开。回执分别保留用户输入与构造后的任务。符合条件的暂停 Session 手动恢复后会有新 run ID，旧 run ID 仍可查询。SSE 连接本身不代表任务成功。

关闭浏览器不会停止任务。服务重启后仍可查看历史与持久化事实；失去进程观测的运行显示 `unknown`。只有配置摘要和运行时能力相符，才可手动恢复已保存为 `paused` 或 `waiting_input` 的 Session。factory 或配置变化可能使恢复不可用。

**当前控制边界：**运行时尚未提供跨进程持久审批 resolver，也没有通用的停止／取消回执。因此 Studio 不展示可操作的审批、暂停、取消或 steer 控件。参考 coding Agent 同样受此限制。会话后续输入不能代替待执行工具调用的审批。

## 本地 API

- `GET /api/agents` 和 `GET /api/agents/{id}/capabilities` 返回本地清单与声明能力。
- `GET /api/sessions?page=1&limit=50&before={id}` 分页返回根会话；`POST /api/sessions/search` 通过受 CSRF 保护的 JSON 请求体提交有长度限制的搜索词，不将其放入 URL。`GET /api/sessions/{id}/turns?after=N` 分页返回轮次；`GET /api/sessions/{turn_id}/runs` 返回已记录的 run ID。旧版启动记录迁移为单轮会话，不补造缺失的 run。
- `POST /api/sessions` 只接受 `agent_id` 和 `task`。只有适配器与当前状态允许时，`POST /api/sessions/{conversation_id}/messages` 才接受 `message`。`PATCH /api/sessions/{conversation_id}` 更新标题、置顶或归档。`POST /api/sessions/{turn_id}/resume` 调用既有 Session 恢复合同。
- `GET /api/sessions/{turn_id}/events?run_id={id}&after=N&limit=100` 读取已脱敏的持久化轨迹；`GET /api/sessions/{turn_id}/stream` 通过 SSE 跟随。重连时先补读轨迹。run ID 必须属于指定轮次。

写请求需要进程会话 Cookie、CSRF 请求头、精确的 loopback Host 与 Origin。服务不提供任意宿主路径、私有 artifact 正文或任意 Python 导入。失败只返回安全错误码，不返回原始异常文本。
